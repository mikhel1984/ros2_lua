# Генерация ROS2 сообщений

Обмен сообщениями играет в ROS2 ключевую роль. Рассмотрим, как он реализован с точки зрения клиентской библиотеки.

Практически все задачи, связанные с передачей и приемом сообщений берут на себя библиотеки [rcl](https://github.com/ros2/rcl) и [rmw](https://github.com/ros2/rmw), нам "только" необходимо обеспечить возможность их создания и обработки. Если ваш язык программирования предоставляет возможность взаимодействовать с полями C структур напрямую, вам очень повезло. В общем случае, придётся писать функции для доступа к данным. 

## Представление сообщений в C

Прежде чем переходить к другим языкам полезно посмотреть, какую структуру имеют сообщения на C. 

На основе msg или idl описания сообщения генератор формирует файлы нескольких типов. Непосредственно структура сообщений описана в файле *тип__struct.h*. В файлах *тип__functions* хранятся функции для инициализации, освобождения, копирования, проверки равенства. В *тип__description.c* содержится детальная информация о структуре сообщений, а в *тип__type_support* - функции генерации сообщений о событиях.

Поля C структуры расположены в том же порядке, в каком они описаны в файле msg. Для элементарных типов используется соответствующий тип из C. Для объекта формируется отдельная структура, которая затем добавляется в сообщение. Если поле представляет собой статический массив, т.е. число элементов известно заранее, аналогичный массив закладывается в C структуру сообщения. В случае динамического массива всё немного интереснее. Для объектов создается структура, содержащая ссылку на выделяемую память, текущее число элементов и размер выделенной памяти. В случае примитивных типов и строк такие структуры заранее определены, поэтому генератор просто добавляет в хэдеры библиотеку *rosidl_runtime_c*.

Библиотека rclpy хранит сообщения в виде классов в Python, для эффективной работы с последовательностями элементарных типов данных используется numpy. Перед непосредственной публикацией сообщения выолняется его серилизация в структуру C, и наоборот, принятое сообщение десериализуется объект Python. Преимуществом такого подхода является гибкость использования (можно применять все стандартные возможности языка) и простота реализации. К недостаткам можно отнести больший размер потребляемой памяти (по сравнению со структурой C).

Поскольку в Lua я не использовал сторонних библиотек, хранение массивов в виде Lua таблиц стало бы весьма ресурсоемким. Поэтому было принято решение использовать сообщения в виде C структур с Lua оберткой. Плюсы: эффективность хранения в памяти, большинство операций выполняются на уровне C, а не Lua. Минусы: значительно вырасла сложность реалзиации (по сравнению с rclpy), потребовалось ввести собственные методы для некоторых операций (типа ...). Сейчас я уже не уверен в правильности принятого решения, но подход вполне работоспособный.

Для каждого пакета сообщений (std_msgs, geometry_msgs и т.д.) формируется отдельная динамическая библиотека...


## rosidl_generator 

Генератор реализуется в виде отдельного ROS2 пакета на Python и включает в себя следующие элементы.

### Папка resource

Здесь содержатся шаблоны для генерации функций сериализации и десериализации сообщений под конкретный язык программирования. Эти шаблоны имеют расширение em и синтаксически являются макросами над языком Python, позволяющими комбинироавть сырой текст с Python инструкциями. Я обнаружил 4 типа таких макросов: для управления генерацией кода, определения промежуточных переменных, подстановки значения в генерируемый текст и комментариев.
```
@# это строчный комментарий

@# генерация в цикле или по условию
@[инициализация блока]@
текст программы
@[  опциональное промежуточное условие, со смещением]@
альтернативный текст программы
@[конец блока]@

@# объявление переменных, функций, прочий код на Python
@{
var = 42
}@

продолжение программы, значение var равно @(var)
```

Основная логика преобразования сообщений определена в файле msg.c.em (название может быть произвольным). Здесь можно реализовать все функции динамической библиотеки для работы с сообщениями, но основными являются методы для сериализации и десериализации. Список полей сообщения определен в переменной *message.structure.members*. Для каждого поля шаблон проверяет тип переменной, является ли она примитивом, объектом или массивом. В последнем случае дополнительно проверяется тип массива (статический или динамический), и какие элементы в нём содержатся (примитивы или объекты). Исходя из этого должна быть реализована логика преобразования в C и обратно.
